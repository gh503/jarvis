# Jarvis v2 — Decision Register

- Status: Accepted for v2
- Date: 2026-10-26
- Rule: 影响产品边界、隐私、记忆权威、平台选择的改动，必须先改这里，再改代码。

| ID | 决策 | 理由 | 后果 |
|---|---|---|---|
| D-001 | **Jarvis 是常驻的私人助手，不是聊天窗口，也不是 coding agent。** | 用户要的是“融入生活和工作的 Jarvis”，不是更强的代码工具。 | 产品以“感知—注意力—对话—行动—记忆”闭环为中心；不把 IDE/终端当主界面。 |
| D-002 | **Linux 桌面优先；macOS 后置。** | 当前开发/验收主机是 Ubuntu；v1 的 macOS MVP 不应继续绑架架构。 | v2 第一出口在 Linux 验收；macOS 代码保留参考，不阻塞 v2。 |
| D-003 | **注意力管理器是显式状态机 + 策略，不交给 LLM 自由决定。** | “什么时候看/说”需要可测试、可解释、可紧急停止；LLM 不适合做实时门控。 | 感知/开口走确定性策略；LLM 只处理“理解和表达”。 |
| D-004 | **按需感知，默认不持续录制屏幕/摄像头/麦克风。** | 隐私是产品前提；Recall 式全量截屏会直接摧毁信任。 | 默认只保留唤醒词环形缓冲；屏幕/摄像头按意图抓取；有可见指示和暂停。 |
| D-005 | **本地优先，远端兜底；DSH 放在 adapter 后面。** | 隐私、延迟、断网可用性；避免被单一模型供应商锁死。 | 唤醒/VAD/ASR/TTS/OCR/embedding 默认本地；复杂推理按隐私级别上云；核心不直接依赖 DSH。 |
| D-006 | **记忆的源是 SQLite；FTS/向量/图都是可重建投影。** | 需要事务、可迁移、可审计；embedding 不是权威数据。 | 删除源必须让投影失效；索引可全量重建；不以向量库为主存储。 |
| D-007 | **记忆分五类：工作、情景、语义、程序、前瞻。** | 不同记忆的保留、召回、权威不同；“一个记忆表”无法表达。 | schema 和召回策略按类型区分；工作记忆不进入长期库。 |
| D-008 | **时间有效性 + 来源 + 冲突链接是一等字段；禁止静默覆盖。** | 用户会改主意；旧事实仍有历史价值；信任来自可追溯。 | 新事实让旧事实 `valid_to` 失效；冲突双方保留；回答带时间和来源。 |
| D-009 | **混合召回：FTS + 向量 + 实体图 + 时间 + 置顶；图谱不是默认。** | 单一向量召回对专名/时间/多跳不稳；图只在多跳有收益。 | 先做 FTS+向量+时间；图用 SQLite 关系表，1–2 跳；没有基准收益就不扩大图。 |
| D-010 | **写入分热路径和后台路径；语音热路径只写“明确记住/承诺/决定”。** | 记忆抽取会拖慢首字延迟；大部分抽取可以异步。 | 语音链路不被记忆阻塞；后台抽取失败不影响对话。 |
| D-011 | **模型只能提议记忆，不能确认记忆。** | 防止模型把猜测写成事实；用户必须拥有最终权威。 | `proposed` 需用户/确定性策略确认；敏感记忆默认不进入模型上下文。 |
| D-012 | **离线巩固是核心能力，不是优化项。** | 人的“秒回”来自提前整理；在线 top-k 无法弥补没组织过的记忆。 | 每晚/空闲做摘要、合并、失效、衰减、连接；巩固失败不阻塞对话。 |
| D-013 | **先做纵向链路，再做广度。** | 十个半成品不如一条“语音→看屏幕→回答→记住”的闭环。 | M0–M2 不接自动提取/多模态扩展；先把一条链路验收。 |
| D-014 | **单用户、单核心、模块化单体；不引入消息队列/微服务。** | 个人助手规模不需要分布式复杂度；SQLite 足够。 | 一个 core 进程；Gateway 可选；出现可测量瓶颈再拆。 |
| D-015 | **不做数字人/虚拟形象。** | 用户明确说“不是必须”；语音 + 屏幕/摄像头上下文优先。 | UI 以状态、字幕、结果卡片为主；不投入 lip-sync/3D  avatar。 |
| D-016 | **高风险动作不因“主动/定时”获得额外授权。** | 主动性不能成为绕过审批的通道。 | 付款、开门、删除大批文件、凭证操作默认禁止或强制确认。 |
| D-017 | **v2 不整体复用 v1 运行时；只复用通过评审的局部能力。** | v1 是 Mac/文字 MVP，产品边界不同；整体复用会继承错误假设。 | 审批/审计/设备身份/恢复可评估复用；核心重写。 |
| D-018 | **评测必须包含弃权、知识更新、冲突、隐私四类。** | 只测 recall@k 会奖励“编造”和“记旧事”。 | 个人基准 150–200 题；不达标不扩功能。 |

## 变更流程

1. 提案：写清“要改什么、为什么、影响哪些文档/模块”。
2. 评审：至少检查隐私、记忆权威、实时延迟、回滚路径。
3. 记录：更新本表，旧决策标记 `Superseded by D-xxx`，不删除历史。
4. 实施：代码/文档同一条 PR；不允许“先写代码，后补 decision”。
