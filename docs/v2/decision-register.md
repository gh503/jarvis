# Jarvis v2 — Decision Register

- Status: Accepted for v2
- Date: 2026-10-26
- Rule: 影响产品边界、隐私、记忆权威、平台选择的改动，必须先改这里，再改代码。

| ID | 决策 | 理由 | 后果 |
|---|---|---|---|
| D-001 | **Jarvis 是常驻的私人助手，不是聊天窗口，也不是 coding agent。** | 用户要的是“融入生活和工作的 Jarvis”，不是更强的代码工具。 | 产品以“感知—注意力—对话—行动—记忆”闭环为中心；不把 IDE/终端当主界面。 |
| D-002 | **Linux 桌面优先；macOS 后置。** | 当前开发/验收主机是 Ubuntu；v1 的 macOS MVP 不应继续绑架架构。 | v2 第一出口在 Linux 验收；macOS 代码保留参考，不阻塞 v2。 |
| D-003 | **注意力管理器是显式状态机 + 策略，不交给 LLM 自由决定。** | “什么时候看/说”需要可测试、可解释、可紧急停止；LLM 不适合做实时门控。 | 感知/开口走确定性策略；LLM 只处理“理解和表达”。 |
| D-004 | **按需感知，默认不持续录制屏幕/摄像头/麦克风。** | 隐私是产品前提；Recall 式全量截屏会直接摧毁信任。 | 默认只保留唤醒词环形缓冲；屏幕/摄像头按意图抓取；有可见指示和暂停。 |
| D-005 | **本地优先，远端兜底；DSH 放在 adapter 后面。** | 隐私、延迟、断网可用性；避免被单一模型供应商锁死。 | 唤醒/VAD/ASR/TTS/OCR/embedding 默认本地；复杂推理按隐私级别上云；核心不直接依赖 DSH。 |
| D-006 | **记忆的源是 SQLite；FTS/向量/图都是可重建投影。** | 需要事务、可迁移、可审计；embedding 不是权威数据。 | 删除源必须让投影失效；索引可全量重建；不以向量库为主存储。 |
| D-007 | **记忆分五类：工作、情景、语义、程序、前瞻。** | 不同记忆的保留、召回、权威不同；“一个记忆表”无法表达。 | schema 和召回策略按类型区分；工作记忆不进入长期库。 |
| D-008 | **时间有效性 + 来源 + 冲突链接是一等字段；禁止静默覆盖。** | 用户会改主意；旧事实仍有历史价值；信任来自可追溯。 | 新事实让旧事实 `valid_to` 失效；冲突双方保留；回答带时间和来源。 |
| D-009 | **混合召回：FTS + 向量 + 实体图 + 时间 + 置顶；图谱不是默认。** | 单一向量召回对专名/时间/多跳不稳；图只在多跳有收益。 | 先做 FTS+向量+时间；图用 SQLite 关系表，1–2 跳；没有基准收益就不扩大图。 |
| D-010 | **写入分热路径和后台路径；语音热路径只写“明确记住/承诺/决定”。** | 记忆抽取会拖慢首字延迟；大部分抽取可以异步。 | 语音链路不被记忆阻塞；后台抽取失败不影响对话。 |
| D-011 | **模型只能提议记忆，不能确认记忆。** | 防止模型把猜测写成事实；用户必须拥有最终权威。 | `proposed` 需用户/确定性策略确认；敏感记忆默认不进入模型上下文。 |
| D-012 | **离线巩固是核心能力，不是优化项。** | 人的“秒回”来自提前整理；在线 top-k 无法弥补没组织过的记忆。 | 每晚/空闲做摘要、合并、失效、衰减、连接；巩固失败不阻塞对话。 |
| D-013 | **先做纵向链路，再做广度。** | 十个半成品不如一条“语音→看屏幕→回答→记住”的闭环。 | M0–M2 不接自动提取/多模态扩展；先把一条链路验收。 |
| D-014 | **单用户、单核心、模块化单体；不引入消息队列/微服务。** | 个人助手规模不需要分布式复杂度；SQLite 足够。 | 一个 core 进程；Gateway 可选；出现可测量瓶颈再拆。 |
| D-015 | **不做数字人/虚拟形象。** | 用户明确说“不是必须”；语音 + 屏幕/摄像头上下文优先。 | UI 以状态、字幕、结果卡片为主；不投入 lip-sync/3D  avatar。 |
| D-016 | **高风险动作不因“主动/定时”获得额外授权。** | 主动性不能成为绕过审批的通道。 | 付款、开门、删除大批文件、凭证操作默认禁止或强制确认。 |
| D-017 | **v2 不整体复用 v1 运行时；只复用通过评审的局部能力。** | v1 是 Mac/文字 MVP，产品边界不同；整体复用会继承错误假设。 | 审批/审计/设备身份/恢复可评估复用；核心重写。 |
| D-018 | **评测必须包含弃权、知识更新、冲突、隐私四类。** | 只测 recall@k 会奖励“编造”和“记旧事”。 | 个人基准 150–200 题；不达标不扩功能。 |
| D-019 | **v2 运行时用 TypeScript / Node 24 模块化单体；UI 用无框架 Web/PWA，Linux 桌面用 Chrome `--app` 壳。** | 当前机器已有 Node 24、v1 的 TS 经验和浏览器；原生类型剥离避免 build step，最快到达可体验的 Linux 助手。Rust/Tauri 保留为后续可选壳/性能 sidecar。 | 核心进程一个；UI 直接消费 HTTP/WS；不引入 Electron/Tauri 构建链；性能瓶颈出现再换壳。 |
| D-020 | **本地模型基线：`qwen2.5:3b` + `nomic-embed-text` + faster-whisper `tiny` + Piper `zh_CN-huayan-medium`；`qwen2.5vl:3b` 仅作可选视觉。** | 在 i5-7300HQ / 4 GB VRAM 实测：3B LLM + nomic 可 100% GPU，热回答 <1 s；qwen3-embedding 会挤爆显存导致 75 s。tiny ASR 热路径 ~2 s；Piper 中文可用。 | 视觉模型不进入实时主路径；换模型必须重跑延迟/隐私验收；模型全部本地。 |
| D-021 | **屏幕理解 OCR-first：先 RapidOCR 本地读文字，再用 LLM 回答；只有显式“用视觉看屏幕”或摄像头无文字时才调用 VLM。** | 这台机器 qwen2.5vl 3B 单帧 40–150 s，不能支撑“实时看屏幕”；OCR 4–8 s，且对办公文本更忠实、可引用。 | VLM 是可选慢路径；OCR 空结果不静默调用 VLM；回答明确说明是否只基于 OCR。 |
| D-022 | **屏幕只走 XDG Desktop Portal 单次授权；Portal 明确拒绝时禁止 X11 绕过。** | 隐私承诺必须强于便利；绕过授权会让“按需感知”变成谎言。X11 仅在 portal 不可用/超时时作为兼容回退。 | 原生 Wayland 窗口标题不可得，窗口黑名单是尽力而为；portal 授权是实际强制点。 |
| D-023 | **远程第一版是 TLS + Bearer/Cookie 令牌的 PWA/WebSocket，不做 WebRTC。** | 手机文字/语音入口已能覆盖大部分远程需求；WebRTC 的 NAT/权限/回声复杂度高，先不引入。 | 手机摄像头/麦克风作为远端输入留到后续；远程必须同时配置 TLS 与 ≥24 字符令牌。 |
| D-024 | **记忆主存用 Node 24 内置 `node:sqlite`（WAL + FTS5 trigram），不引入 sqlite-vec/LanceDB。** | 单用户、万级条目；SQLite 事务/迁移/备份最简单；向量用 BLOB + 进程内 cosine，避免额外服务。 | 向量扫描上限 5000 条；超过后需要 ANN 或分片；FTS 短中文查询用 LIKE 回退。 |
| D-025 | **默认静默 + 按住说话；不做唤醒词常听、不做持续 VAD。** | 当前 CPU/隐私预算下，常听麦克风收益不抵风险；PTT 已能验证完整语音闭环。 | 唤醒词/VAD 必须单独立项并重新评估 CPU、误唤醒、隐私指示。 |
| D-026 | **工具执行先做“一次性确认动作”：只允许打开 http/https 网页与文件管理器/浏览器；60 秒过期；执行写审计；不做任意 shell。** | 在“能动手”和高安全之间取最小可验证交集；用户明确点击“允许一次”才执行，避免模型直接产生副作用。 | 不能写文件、不能开终端；更多工具必须复用同一审批/审计模型并单独评审。 |
| D-027 | **本地模型常驻 + 启动预热：Ollama `keep_alive=24h`，启动时加载 LLM/nomic；Piper 使用常驻 `--json-input` worker，并按短句流式合成。** | 首次回答慢的主因是模型冷加载（实测冷 4–9 s、热 0.8–1.5 s）与每次启动 Piper 的 2–3 s；预热/常驻把首轮降到可接受，短句合成让音频在文本完成前开始。 | 常驻 LLM+nomic 约占 2.5 GB 显存/内存；可用 `JARVIS_OLLAMA_KEEP_ALIVE=5m` 回收。Piper 进程异常退出时自动重启。 |
| D-028 | **模型来源运行时切换：Web 设置里编辑 local / remote，服务端 `data/model-config.json`（0600）持久化，测试成功后原子切换，下一轮立即生效；远端只支持 OpenAI-compatible（Bearer），非 loopback 强制 HTTPS，Key 不回显；远端未配置 embedding/vision 时复用本地。** | 用户要求“界面点击配置、点一下切换”，且不能让每次换模型都改 env 重启；把密钥留在服务端、把测试放在写盘前，避免坏配置和密钥泄漏。 | 远端对话会把上下文发给服务商；UI 和文档明确提示。切换不打断进行中的一轮，下一轮生效。 |



## 变更流程

1. 提案：写清“要改什么、为什么、影响哪些文档/模块”。
2. 评审：至少检查隐私、记忆权威、实时延迟、回滚路径。
3. 记录：更新本表，旧决策标记 `Superseded by D-xxx`，不删除历史。
4. 实施：代码/文档同一条 PR；不允许“先写代码，后补 decision”。

## 待定（Open）

以下不阻塞当前纵向链路，但扩功能前必须补 decision：

- 桌面壳是否迁移到 Tauri（当前 Chrome `--app` 已可用）。
- 本地静态加密：SQLCipher vs 应用层字段加密。
- 视觉模型替换（目标：4 GB 显存内全 GPU、中文可用）。
- 手机端 WebRTC 与设备配对/撤销。
- 唤醒词与 VAD 的默认开关和误唤醒预算。
- 更多工具执行（文件/日历/浏览器自动化）的审批与回滚模型；D-026 已固定最小打开动作。
