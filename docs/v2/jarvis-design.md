# Jarvis v2 — 产品与系统设计

- Status: Baseline for v2
- Date: 2026-10-26
- Related: [memory-design.md](memory-design.md), [decision-register.md](decision-register.md)

## 1. 产品形态

Jarvis 不是一个需要“打开”的 App，而是一个常驻的桌面存在：

- 桌面边缘一个小浮窗/状态球，默认不抢焦点；
- 全局快捷键按住说话，松开即发送；
- 说话时有明确状态：正在听 / 正在看屏幕 / 正在看摄像头 / 正在想 / 正在做；
- 回答默认用语音，复杂内容在浮窗里展开；
- 需要上下文时，先问一句或按已有授权抓取，不偷偷持续采集；
- 用户说“停”时，麦克风、摄像头、屏幕采集立刻停止，并有明显指示。

### 一个真实的工作日

| 时间 | 场景 | Jarvis 的行为 |
|---|---|---|
| 09:00 | 坐下，说“早” | 读日历/待办，用 20 秒语音简报；不念不重要的邮件 |
| 09:40 | 看着一份合同，说“看下这个” | 识别到“这个”的指示意图，抓当前窗口/选区，指出风险条款 |
| 11:00 | 开会中 | 检测到会议应用/麦克风占用，主动消息只进静默队列，不发声 |
| 14:00 | 说“找一下上周那张发票” | 先搜文件/邮件；找不到再问“要我看屏幕还是摄像头？” |
| 16:00 | 在厨房，说“我手上这个是什么” | 抓一帧摄像头，本地识别后回答；不上传整段视频 |
| 18:00 | 任务完成 | 只在空闲时用轻提示；如果用户在忙，转为静默记录 |

## 2. 设计原则

1. **沉默是默认，开口是决策。** 能回答不等于该回答；能主动不等于该打扰。
2. **按需感知，不做持续录制。** 默认只监听唤醒词/按键；屏幕和摄像头按意图抓取。
3. **先本地，后远端。** 唤醒、VAD、人脸/在场检测、OCR、embedding 默认本地；复杂推理才上云。
4. **每个“看/听/说”都可解释。** 用户能知道它为什么看、看了什么、为什么开口。
5. **记忆是产品，不是日志。** 记忆必须可查看、可纠正、可删除、可解释。
6. **行动有边界。** 读取/总结可以自动；有副作用、不可逆、涉及隐私的动作必须确认。
7. **先纵向跑通，再横向扩展。** 一条“语音 → 看屏幕 → 回答 → 记住”的链路，比十个半成品能力重要。

### 进程边界

- **jarvis-core**：唯一常驻核心；注意力、对话、记忆、工具、模型路由都在这里，先做模块化单体。
- **jarvis-gateway**：可选，手机/远程接入时启用；负责认证、TLS、会话和事件转发。桌面本地可直连 core 的 Unix socket。
- **jarvis-node**：可选，其他电脑/设备上的能力代理；第一版与 core 同机，不引入。
- **不把 Harness 当核心**：Harness 作为 `ModelRuntime` / `ToolRuntime` 适配器之一，放在边界后面。

## 4. 注意力管理器（核心）

注意力管理器是一个**显式状态机 + 可审计策略**，不是让大模型“自由决定”。

### 4.1 状态

```text
Idle
  ├─ wake word / hotkey / 用户直呼其名 → Listening
  └─ 定时/事件触发 → ConsideringProactive

Listening
  ├─ VAD 检测到说话 → CapturingUtterance
  └─ 静音超时 → Idle

CapturingUtterance
  ├─ 语音结束 → Understanding
  └─ 用户取消 → Idle

Understanding
  ├─ 需要屏幕 → NeedScreen
  ├─ 需要摄像头 → NeedCamera
  ├─ 需要记忆 → Recalling
  └─ 可直接回答 → Responding

NeedScreen / NeedCamera
  ├─ 有授权/低敏感 → CapturingContext → Understanding
  ├─ 需确认 → AskingPermission
  └─ 用户拒绝 → Responding("好，不看")

Responding
  ├─ 用户打断 → Listening
  └─ 回答完成 → FollowUp(5–10s) → Idle
```

### 4.2 该看哪一路

| 用户信号 | 默认动作 | 说明 |
|---|---|---|
| “看下这个 / 这页 / 这份合同” | 屏幕 | 有明确的屏幕指示词 |
| “你看我这里 / 我手上这个 / 桌上是什么” | 摄像头 | 指向现实世界 |
| “帮我找一下……” | 先文件/邮件检索 | 不立刻抓屏幕 |
| “现在这样行吗 / 我穿这个” | 摄像头 | 外观/场景判断 |
| 只说“看”，没说看哪 | 先屏幕，再问一次 | 办公场景屏幕概率更高 |
| 置信度低 | 只问一句“屏幕还是摄像头？” | 问一次后记住选择 |

**默认策略：工作相关优先屏幕，现实世界才用摄像头。**

### 4.3 感知预算

- 每次用户回合最多 **1 张屏幕截图 + 1 个 OCR/视觉区域**；
- 摄像头最多 **3 帧**，不做连续视频流；
- 屏幕/摄像头帧默认只在内存中处理，不落盘；需要记忆时只存摘要/缩略图，并标记来源；
- 单次上下文注入上限 **4k tokens**；超出时先摘要/裁剪，不把整屏原始像素塞进模型。

### 4.4 该不该说话

给每条主动消息算一个**打扰分数**：

```text
interrupt_score =
  0.30 紧急度（截止/有人等/失败）
+ 0.20 用户相关性（当前任务/当前人）
+ 0.15 时效性（现在不说就失效）
+ 0.15 用户偏好（历史接受度）
- 0.30 打断成本（打字/会议/专注/刚被打扰）
- 0.20 频道成本（语音 > 弹窗 > 静默）
```

三个出口：

| 分数/场景 | 通道 |
|---|---|
| 用户主动问、明确紧急 | 语音 |
| 重要但不紧急 | 浮窗/角标 |
| 低价值/用户在忙 | 静默记录，进时间线 |

硬规则：

- 检测到会议、屏幕共享、麦克风被其他应用占用 → 禁止主动语音；
- 用户说“我在忙/别烦我” → 进入免打扰，只记录；
- 每天主动语音有预算（默认 5 次），超出后只发文字；
- 用户一开口，TTS 立即停止，未播完的内容转为文字；
- 回答后保留 5–10 秒追问窗口，然后关闭麦克风。

### 4.5 可解释

每次感知/开口都写一条 `attention.decision`：

```json
{
  "at": "2026-10-26T09:40:12+08:00",
  "trigger": "user_reference",
  "sensors": ["screen"],
  "reason": "deictic_reference:这个",
  "sensitive": false,
  "spoken": true,
  "interrupt_score": 0.82
}
```

用户可以在“为什么看/为什么说”里看到这条记录；默认保留 30 天。

## 5. 实时对话

### 5.1 链路

```text
mic → 20–40ms PCM chunks → VAD → streaming ASR
    → conversation orchestrator → model router
    → streaming text → streaming TTS → speaker
```

### 5.2 延迟预算

| 阶段 | 目标 |
|---|---|
| 唤醒/按键到开始录音 | < 150 ms |
| 说完到 ASR final | < 500 ms（本地） |
| 说完到首个文本 token | < 800 ms |
| 说完到首个音频包 | < 1.5 s |
| 用户打断到 TTS 停止 | < 100 ms |
| 记忆召回（本地） | p95 < 100 ms |

### 5.3 打断与追问

- 全双工：用户说话时，TTS 立刻停，播放缓冲丢弃；
- 支持“等等/不对/继续”这类短指令；
- 回答结束后进入 FollowUp，不要求每次重新按快捷键；
- 长时间沉默自动回到 Idle，释放麦克风。

### 5.4 本地/远端路由

| 能力 | 默认 | 兜底 |
|---|---|---|
| 唤醒词、VAD | 本地 | 无 |
| ASR | 本地小模型 | 云端 |
| TTS | 本地 | 云端音色 |
| 人脸/在场检测 | 本地 | 无 |
| OCR/屏幕理解 | 本地 OCR + 小视觉模型 | 云端多模态 |
| 复杂推理/长文档 | 本地小模型（能则本地） | 云端 |
| Embedding | 本地 | 云端（需授权） |

路由规则：

- `privacy=local-only` 的请求永远不出机器；
- `privacy=standard` 可上云，但只发必要文本/裁剪帧；
- 敏感应用（密码管理器、网银、私密聊天）不抓屏、不上传；
- 网络断开时自动降级到本地能力，并明确告诉用户“现在只能本地处理”。

## 6. 感官层

### 6.1 屏幕

- Linux 优先用 XDG Desktop Portal（ScreenCast/RemoteDesktop）拿授权，不直接读 X11/Wayland 缓冲区；
- 先取当前窗口标题、应用名、选区等**轻量元数据**；需要时再截屏；
- 截图后本地 OCR，按需裁剪区域；只把必要区域送视觉模型；
- 默认不持续录屏；不建立“Recall 式”全量截图库。

### 6.2 摄像头

- 默认关闭；用户说“看我/这个”或明确开启时抓帧；
- 本地先做人脸/在场/模糊检测；无人像或低质量时直接说“没看清”；
- 不保存原始视频；需要记忆时只存摘要和可删除的缩略图；
- 摄像头开启时必须有物理/软件指示灯和可见状态。

### 6.3 麦克风

- 默认只保留环形缓冲，用于唤醒词检测；
- 唤醒后开始流式 ASR；未唤醒的音频不落盘、不上传；
- 提供硬件静音/软件暂停；暂停后状态必须明显。

## 7. 行动层

- 工具注册表：文件、浏览器、日历、提醒、剪贴板、应用启动。
- 每个工具声明：参数 schema、风险等级、是否需要审批、是否可逆、超时。
- 风险等级：
  - `read`：自动；
  - `write`：默认自动，可配置确认；
  - `irreversible` / `external`：必须确认；
  - `financial` / `physical` / `credential`：默认禁止，除非显式开启。
- 所有工具调用写审计；高风险动作记录“谁批准、批准了什么、何时过期”。
- 执行结果要回读验证，不能把“命令已发送”当成“事情已做成”。

## 8. 客户端与部署

第一平台是 **Linux 桌面**；macOS 后置，手机是远程客户端。

### 桌面

- 首选 Tauri 或 egui 做浮窗；不把整个 UI 做成浏览器标签页；
- 全局快捷键、托盘、开机自启；
- 本地 IPC 用 Unix domain socket，权限 `0600`；
- 浮窗只显示状态、字幕、结果卡片；复杂内容可展开。

### 手机

- 第一阶段 PWA：文字、按住说话、审批、通知；
- 第二阶段 WebRTC：实时语音/视频，手机作为远程麦克风/摄像头；
- 手机不持有模型密钥；通过 Gateway 短期会话访问。

### 单机优先

- 一个 core 进程，模块化单体；
- 不引入 Redis/NATS/Kafka；SQLite + 事务 outbox 足够；
- 只有出现可测量的拆分需求时才拆服务。

## 9. 隐私与安全

- 默认本地；云端调用逐类授权；
- 屏幕/摄像头采集有可见指示，可一键暂停；
- 敏感应用/窗口黑名单，永不自动采集；
- 记忆可查看、纠正、删除、导出；
- 原始音视频默认不落盘；摘要/缩略图有 TTL；
- 远程访问必须经过认证 Gateway，默认只允许私网/overlay；
- 高风险动作默认拒绝，不因“定时/主动”获得额外授权。

## 10. 失败模式

| 失败 | 行为 |
|---|---|
| ASR 置信度低 | 复述确认，不猜 |
| 视觉模型看不清 | 说“没看清”，请用户靠近/重拍 |
| 记忆召回为空 | 明确说“我没找到”，不编 |
| 云端超时/断网 | 降级本地，告知用户 |
| 工具执行失败 | 报告失败原因，不假装成功 |
| 用户打断 | 立即停 TTS，丢弃未播内容 |
| 麦克风/摄像头被占用 | 明确提示，不偷偷重试 |
| 主动消息被忽略 | 降低同类打扰权重，不重复轰炸 |

## 11. V2 里程碑

### M0 — 骨架（设计冻结后）

- core 进程、Unix socket、状态机骨架；
- 配置、日志、审计、模型适配接口；
- 一个可测试的 `AttentionManager`，先用假传感器。

### M1 — 语音纵向链路

- 按住说话 → 本地/远端 ASR → 模型 → TTS；
- 打断、追问、错误提示；
- 延迟打点。

### M2 — 屏幕上下文

- Portal 授权、当前窗口元数据、按需截图、OCR；
- “看下这个”意图路由；
- 上下文预算和敏感窗口过滤。

### M3 — 记忆 v2 最小闭环

- 记忆 schema、写入、召回、来源展示；
- 显式“记住这个” + 晚间巩固；
- 记忆查看器（先 CLI/最小 UI）。

### M4 — 主动性与摄像头

- 日历/任务/截止触发；
- 打扰分数、静默队列、免打扰；
- 按需摄像头抓帧。

### M5 — 远程与手机

- Gateway 认证、PWA、WebRTC 语音；
- 手机审批/通知。

## 12. 验收（v2 第一出口）

1. 用户说“看下这个合同”，Jarvis 能判断看屏幕、抓当前窗口、指出至少一条风险，并说明来源。
2. 用户在会议中，Jarvis 不主动发声；同一消息进入静默队列。
3. 用户说“记住我对花生过敏”，三天后问“晚上吃什么”，Jarvis 能召回并说明“这是你之前确认的”。
4. 用户说“忘掉这件事”，Jarvis 删除后不再召回，并能在记忆查看器里看到删除记录。
5. 用户打断 TTS，100ms 内停止；追问“那第二点呢”能接上上下文。
6. 断网时，语音/记忆/本地文件仍可用；需要云端的请求明确降级。
7. 摄像头/屏幕采集有可见指示；用户说“停”后立即停止。
8. 每个主动语音消息都能在审计里看到“为什么说、依据是什么”。

## 13. 设计依据

以下是影响本设计的外部实践，作为参考而不是依赖：

- **Gemini Live best practices**：20–40ms 音频分块、打断时丢弃播放缓冲、上下文压缩、会话恢复——直接约束了本文的实时链路和延迟预算 [文档](https://ai.google.dev/gemini-api/docs/live-api/best-practices)。
- **Google Proactive Audio**：模型可以在不相关时选择不回应，但“主动发起”仍主要靠外部调度；这支持了 D-003 的独立注意力管理器 [说明](https://cloud.google.com/blog/topics/developers-practitioners/how-to-use-gemini-live-api-native-audio-in-vertex-ai)。
- **Project Astra**：屏幕共享、摄像头/视频理解、眼镜形态，验证了“按需多模态上下文”的产品方向 [项目页](https://deepmind.google/models/project-astra/)。
- **Microsoft Recall**：本地处理、opt-in、暂停/过滤/删除、Windows Hello、敏感信息过滤；即便如此仍有隐私反弹，说明“可见、可控、默认关闭”不是可选项 [Microsoft Learn](https://learn.microsoft.com/en-us/windows/client-management/manage-recall)。
- **Letta sleep-time compute**：离线整理记忆能显著降低在线计算；这支持把巩固放在后台，而不是每次对话都重读全部历史 [Letta](https://www.letta.com/blog/sleep-time-compute/)、[论文](https://arxiv.org/abs/2504.13171)。

厂商/论文中的性能数字只作方向参考，不作为本项目的验收指标。

## 14. Open questions

- 桌面 UI 最终选 Tauri 还是 egui（取决于 Linux 透明浮窗/输入法/托盘体验）。
- 本地 ASR/TTS 模型选型（取决于当前机器是否有 GPU，以及中文效果）。
- 手机第一阶段用 PWA 还是直接 React Native（取决于后台音频/推送需求）。
- 是否支持唤醒词常听（隐私 vs 便利），默认先按住说话。

未决项不阻塞 M0–M2；涉及隐私默认值的决定必须在实现前补 decision。
